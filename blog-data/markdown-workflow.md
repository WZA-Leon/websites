# Markdown 写作工作流

写一篇能长期维护的文章，重点不是“写得多”，而是让下一次修改足够轻松。

## 1. 先写结构，再写句子

我通常先把文章拆成几个二级标题，再在每个标题下面放三到五个要点。标题是骨架，句子只是后来长出来的血肉。

- 这篇文章要解决什么问题？
- 读者需要先知道什么？
- 哪些内容可以放进代码块、表格或清单？
- 最后要不要留一个“下一步”？

## 2. 文件命名

使用稳定的英文 id，例如：

```text
blog-data/markdown-workflow.md
project-data/work1/README.md
```

文章标题可以改，文件名尽量不要改。这样站内链接、索引和收藏都不会失效。

## 3. 常用语法

| 场景 | 写法 |
| --- | --- |
| 二级标题 | `## 标题` |
| 强调 | `**重点**` |
| 行内代码 | `` `code` `` |
| 链接 | `[文字](https://example.com)` |
| 图片 | `![说明](image.png)` |
| 引用 | `> 一句话` |

## 4. 发布前检查

- 一级标题只保留一个，页面会单独展示标题
- 相对链接和图片路径能正常访问
- 代码块标注语言
- 长表格在移动端不会溢出
- 至少通读一遍，删掉重复的句子

## 5. 让内容可复用

同一份笔记可以拆成博客文章、项目文档和分享说明。不要为了“每个栏目都要有内容”而复制整篇文章，换一个角度重写开头和结尾即可。

> 好的文档不是一次写完的，而是被不断使用、修正和补充的。
